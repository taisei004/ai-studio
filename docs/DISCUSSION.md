## ユーザーが明示した方向

- 専門分野ごとのAIに仕事を任せ、進捗を可視化するバーチャルオフィスを作りたい。
- 自分が運用しやすいことを重視する。
- デザイン比較のA案「ピクセルアート型」で確定。
- 初期の基盤作りはCodex。10/20以降に利用予定のClaudeをメイン開発に使いたい。

## 会話で提案された仕様と今回の採用範囲

- 仮称AI STUDIO。「眺めて楽しい、任せて便利なAI制作オフィス」。
- 案件、AI社員、タスク、承認、成果物を管理する汎用基盤。最初の用途はパレプロEX番組制作。
- 6人: Producer / Researcher / Writer / Designer / Material Artist / Reviewer。
- オフィス中心、社員選択で右パネルに詳細。書類を承認・修正依頼・保留する。
- 状態は待機中・作業中・承認待ち・完了・エラー。処理結果と状態に基づく表示にする。
- 作業ログは参照資料、実行処理、成果物、エラーなどの記録を対象とし、内部思考を表示する仕様にはしない。
- React / TypeScript / Vite / Tailwind / PixiJS / Node / SQLiteを基本構成とする。
- v0.1では実AI接続をせず、モックと実行インターフェースを作る。
- README、共通ルール、製品仕様、設計、ロードマップ、引き継ぎ文書を用意する。

## 将来構想

- Codex CLI / Claude Codeへの接続、仕事の割当と自動実行、リアルタイム更新。
- AI同士の連携、部屋への移動や会議などの演出。
- Webアプリ・MV・グラフィック制作テンプレート。
- Tauri等によるデスクトップアプリ化。

## 検証する目標・未確定事項

- 会話内の配信準備7〜12時間→2時間20分〜4時間10分は仮の削減目標。効果は未検証。
- デジハリ提供Claudeの認証方式、CLI利用可否、モデル、上限・課金条件。
- キャラクター素材、元のA案への見た目の寄せ方、歩行・会議等の演出。
- 実AIの実行権限、並列数、キャンセル、再試行、成果物の形式。

今回の実装判断: 新規フォルダーに独立したローカルプロジェクトを作成。工程はまず直列。SQLiteは単一ユーザー向けに型付き状態スナップショットを保存し、実AI接続前に正規化・実行キューを検討する。
